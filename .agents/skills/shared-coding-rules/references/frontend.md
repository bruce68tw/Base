# 前端開發規則

適用於 TypeScript 前端與瀏覽器互動；共用模組的函式簽名、DOM 與資料格式仍以各模組文件及來源為準。此文件逐步收集已確認的慣例。

## 函數命名（使用者已確認）

前端函數使用 lowerCamelCase。變數與 MVC 功能檔案對應見 [主 skill 命名規則](../SKILL.md#命名規則使用者已確認)。

## MVC／Razor 前端分工（使用者已確認）

Razor View 負責頁面呈現，前端互動邏輯放在對應的 TypeScript 檔，避免在 View 內堆放 JavaScript。對應檔案依 [主 skill 的 MVC 命名規則](../SKILL.md#mvc-資料表功能對應)；此原則不禁止必要的初始化程式，也不延伸至 Flutter。

## 非同步流程

建構函式可以啟動非同步方法，但本身不能宣告為 async 或直接使用 await，也不會等待該方法完成。必須等待後端結果的後續步驟放在非同步方法的 await 之後；只有呼叫端確實需要等待整體初始化時，才引入可等待的初始化入口，不為單一流程全面改造建立方式。

## 等待視窗與共用請求

顯示等待視窗後發送非同步請求時，成功與失敗都必須解除等待狀態，自管視窗可在 finally 清理。若既有共用 Ajax 已負責顯示與解除遮罩，沿用其機制，避免再疊加一層相同遮罩；先核對所用方法的實際設定。

## CSRF 傳送與驗證分工

後端全域防偽驗證不會替前端送出權杖。jQuery 的 ajaxSetup 只影響 jQuery 請求，不會套用到原生 fetch；改用 fetch 時，依後端契約自行附加防偽權杖。避免將登入 Cookie、CSP 或其他安全標頭當成權杖的替代品。

未涵蓋的命名與排版慣例沿用工作專案，不自行補造全域標準。
