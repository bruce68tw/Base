# 後端開發規則

適用於 C# 後端，並明確區分底層共用模組與應用層。共用 API 的參數、模型及框架行為仍以各模組自己的 skill 與實際來源為準。

## 函數命名（使用者已確認）

後端函數使用 PascalCase。變數與 MVC 功能檔案對應見 [主 skill 命名規則](../SKILL.md#命名規則使用者已確認)。

## MVC 程式組織（使用者已確認）

C# MVC 後端的 Controller 負責接收請求與回傳結果，商業邏輯放在 Service。

## C# 排版（使用者已確認）

每層使用 4 個空白縮排；使用大括號時，大括號另起一行。單一陳述式條件判斷仍依「條件判斷」段落約定省略大括號。此排版規則僅適用 C# 後端。

## 區域變數型別（使用者已確認）

C# 區域變數的型別明確可辨時使用 `var`；需要指定型別或無法推斷時，明寫型別。此規則不延伸至成員、參數或前端程式。

## 可空值判斷與型別轉換（使用者已確認）

C# 後端使用 Base 時，可空值的判斷與型別轉換優先使用 Base 既有工具函數，沒有適用工具時才自行處理。工具查找與契約核對依 [主 skill 重用原則](../SKILL.md#優先重用既有共用程式)，不憑名稱猜測 API 或轉換語意。此規則不延伸至無法直接呼叫 C# Base 工具的 TypeScript 或 Flutter。

## 條件判斷（使用者已確認）

C# 條件判斷的主體只有單一陳述式時，省略大括號。陳述式與條件寫在同列或換行尚未確認；此規則不擴大至迴圈或前端程式。

後端優先提早返回，減少巢狀判斷：先處理無效或特殊輸入並返回，使主要流程清楚。此為預設原則，不要求一律多出口，也不改變既有資源釋放或錯誤契約。

## 應用功能 Service 例外處理（使用者已確認）

此規則適用於有回傳值且採用此契約的 C# 應用功能 Service。以 `try/catch` 捕捉例外，在 `catch (Exception)` 處直接呼叫 `_Log.Error("xxx")`，將錯誤訊息以字串傳入，然後統一寫 `return default;`，由 C# 依回傳型別決定預設值，例如 `string?` 得到 `null`。不自行換成空字串、空集合，或依型別逐一硬寫 `null`、`0`。

此具體 Log 呼叫僅適用 C#，不套用至 TypeScript；日誌內容仍遵守下節的敏感資料限制。`void` 方法不套用 `return default;`，非同步方法依實際回傳契約處理。此規則不套用所有 Base 共用模組，也不要求重寫舊程式；共用程式維持下節既有契約。呼叫端依此預設回傳契約判斷失敗。

## 共用模組錯誤處理（使用者已確認）

- 底層共用方法遇到錯誤時，呼叫 `_Log.Error` 記錄錯誤，並回傳該方法約定的空白資料，不向呼叫端拋出例外。
- 空值須依方法回傳型別與既有契約決定。例如回傳字串的方法使用 `""`；其他型別核對原有 null、空集合或結果物件約定，不任意變更公開型別。
- 在共用方法邊界涵蓋預期失敗與例外，避免只處理網路錯誤、卻讓輸入檢查或解析例外向外逸出。
- 日誌不得包含憑證、含秘密的網址、完整服務錯誤本文或使用者完整輸入。優先記錄錯誤分類、必要的狀態碼與例外類型，不直接串接可能含秘密的 exception.Message。
- 應用層呼叫共用方法後，檢查該方法約定的空回傳，再決定使用者訊息與 HTTP／JSON 回應；不把底層錯誤細節直接顯示給使用者。

範例：[GeminiSvc.AskA](../../../../BaseAI/Services/GeminiSvc.cs) 失敗呼叫 `_Log.Error` 後回傳空字串，成功保留該方法既有回應契約。這是方法範例，不表示整個服務或所有舊方法都已符合上述原則。

### 既有契約與例外

既有模組可能仍有拋例外或傳遞取消的契約。修改前核對基底類別、衍生實作與呼叫端，不因本規則自動全面改造其他方法；需要變更時明確處理相容性。此共用層原則不代表所有 Controller、框架驗證或應用層都要吞掉錯誤並回傳成功。

## 前後端驗證分工

後端全域防偽驗證與個別 action 的驗證標記可能重複；是否省略個別標記，依實際服務註冊與 action 範圍確認。即使使用全域驗證，前端仍須依契約送出權杖。
