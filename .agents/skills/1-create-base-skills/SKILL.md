# 整理 Base 程式知識庫

Base 在此作為 AI 撰寫應用程式的參考知識庫。本 skill 只整理文件，不修改 Base 程式、不還原套件、不編譯或執行子專案。

## 準備

- 先查看 `git status --short`，保留既有修改；讀取根目錄及目標子專案的 `AGENTS.md`（如有）。
- 以各獨立 `.csproj` 子專案為單位，閱讀專案設定與原始碼，辨識現行功能；排除 `Compile Remove` 指定來源及舊版、備份檔。略過根目錄名稱以 `zz_` 開頭的子目錄。
- 文件使用繁體中文，程式識別名稱維持原樣；用途依原始碼核對，不猜測未確認的功能。

## 1. 先整理子專案文件

在各子專案的 `.agents/` 直接產生或更新以下一般 Markdown；沒有適用項目的分類不新建空文件。

| 檔案 | 內容 |
| --- | --- |
| `1-static-services.md` | 靜態工具類別與用途 |
| `2-instance-services.md` | 實例服務與用途 |
| `3-models.md` | DTO、設定與輸入輸出模型 |
| `4-enums.md` | 列舉與常數 |
| `5-contracts.md` | 介面與抽象基底契約 |

每份文件包含標題、資料更新日期，以及「類別名稱、用途說明」清單：

```markdown
# 資料模型

資料更新日期：YYYY-MM-DD

| 類別名稱 | 用途說明 |
| --- | --- |
| [類別名稱](相對原始檔路徑) | 具體說明用途。 |
```

- 日期表示最後核對來源的日期，單純排版不更新日期。
- 類別名稱直接連到原始檔，不另設原始碼欄。名稱有歧義時補 namespace 或路徑。
- 用途具體說明可處理的工作或資料，不只改寫名稱，不複製完整原始碼。
- 必要的類別詳解、使用前提或範例放在同一文件下方；不另建 overview、類別文件或子專案 skills。
- zz_ 開頭的檔名不處理。

## 2. 再整理大 Base 總覽

依各子專案剛整理完成的 `1-static-services.md`、`2-instance-services.md`、`5-contracts.md`，彙整 `.agents/skills/projects-intro.md`。缺少的分類略過，說明不清楚時回查原始碼。

- 只列子專案名稱與用途，每個子專案以名稱為標題，下方使用條列。
- 用途必須具體，讓 AI 與人員能理解有哪些功能；一列能完整描述就不增加條列。
- 不寫籠統、重複的適用情境，不列類別、方法、初始化程序或實作供應商分工。

例如：

```markdown
## MsOffice

- 提供 Excel 資料匯入、範本填值，以及 Word 套表與文件合併。
```

## 完成檢查

檢查分類、原始檔連結、日期與用途說明；總覽須符合子專案服務及契約內容。不主動刪除既有文件或 skills；若任務包含搬移，修正受影響的引用。最後簡要回報更新範圍與尚未確認的內容。
