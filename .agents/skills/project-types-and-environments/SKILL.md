# 專案種類與開發環境

本檔為第一主題的討論初稿，依使用者已確認內容維護。「待確認」與「建議」不能當成既定規則。實際專案設定與本檔不一致時，列出差異再確認，不逕自升級版本或更換架構。

專案由程式設計師建立；AI 僅在既有專案開發功能。標準專案範本供目錄結構與寫法參考，不授權 AI 建立專案，也不將建立專案流程列為必要項目。

## 使用方式與主題界線

- 先辨識應用種類，依對應段落採用已確認資訊。只釐清影響當前工作的缺漏，不為補齊所有欄位阻擋可獨立進行的工作。
- 版本為已確認下限或主版本；SDK、套件與工具精確版本仍須核對目標專案，不直接採用最新版。
- 範本與共用模組僅適用於明確確認的種類，不將後台的設定推廣至其他種類。未列出的技術與架構不可由其他種類類推。
- 本 skill 只維護第一主題。其他四主題僅界定範圍：風格原則沿用 [shared-coding-rules](../shared-coding-rules/SKILL.md)；共用程式的 API 用法留在各模組 skill；功能實作與驗收、商業規則與資料庫留待後續討論，本檔不增訂其規則。
- 跨模組與應用的分類資訊維持於大 Base 根目錄。使用模組時依實際相依讀取子專案 AGENTS 與使用 skill，不在此複製 API 契約。

### 後台目錄約定

以下為使用者已確認的約定，僅適用後台管理：

- `Controllers/`、`Services/`、`Views/`、`wwwroot/`：按 ASP.NET Core 專案常用目錄理解，不重複框架基本用途；其中 `Services/` 是專案慣用目錄，並非框架強制建立。
- `Enums/`：檔名結尾 `Enum` 表示數字，`Estr` 表示字串；不據此推論字串列舉的語言實作方式。
- `Models/`：放 model 資料。
- `Services/_Xp.cs`：該專案的共用程式，包含該專案商業規則；不等同 Base 共用模組。
- `Services/_XpCode.cs`：處理下拉式欄位。
- `_src/`：前端 TypeScript 原始程式。
- `_src/tsBase/`：前端共用程式，此目錄在每個專案的內容都相同；`dto/` 放 model、`enum/` 放列舉、`svc/` 放服務。
- `_src/tsView/`：各功能的 TypeScript 程式，檔名同功能名稱。

本輪指定討論但用途尚待確認的項目：`Models/MyConfigDto.cs`、`Properties/` 與 `Properties/launchSettings.json`、`Services/MyBaseUserSvc.cs`、`_src/tsView/XpVo.ts`、`_template/`、`_upload/`。其中 `_upload/` 僅為使用者指定，尚未核實存在，不推定其用途或要求建立。
